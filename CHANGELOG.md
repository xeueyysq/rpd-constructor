# История версий

Версия одна на весь продукт (сервер и клиент) и следует [SemVer](https://semver.org/lang/ru/). Порядок выпуска описан в [docs/CONVENTIONS.md](docs/CONVENTIONS.md#версии-и-релизы).

Версии 1.x восстановлены по выкладкам в `main` прежних репозиториев сервера и клиента. Тегов у них нет, первый тег монорепозитория — `v2.0.0`.

## [2.1.2] — 2026-10-03

Исправления по итогам репетиции выкладки 2.1.1 на копии прода. С 1.x обновляйтесь сразу на эту версию.

### Важно при обновлении

- После обновления все пользователи входят заново: миграция `0002_refresh_sessions` удаляет прежние сессии.
- Открытые вкладки нужно перезагрузить: старый клиент не понимает новый ответ таблицы комплекта.

### Исправлено

- Из системы больше не выкидывает при параллельных запросах и перезагрузке страницы. У каждой сессии свой refresh-токен, в БД хранится только его хэш. Ротация атомарная, а повтор предыдущего токена в течение 10 с не обрывает параллельные запросы. Клиент обновляет токен один раз на все запросы, ошибки сети и 5xx сессию не сбрасывают, после входа открывается исходная страница. Истёкший access-токен даёт 401, нехватка прав — 403, выход срабатывает всегда.
- «Готово» можно отметить только после «Взять в работу»; сервер тоже отклоняет такой переход.
- Действия РПД показываются по активной роли: действия преподавателя больше не попадают к РОП. Excel ФОС недоступен, пока в комплекте нет компетенций.
- Метка поля ввода не съезжает вниз, если под полем есть подсказка.
- Цвет вторичных и цветных подписей снова применяется: в MUI 9 проп `color="text.secondary"` молча игнорировался. ESLint теперь запрещает такие пропсы.

### Изменено

- Таблица комплекта:
  - колонки как в 1.5, у каждого преподавателя — личная отметка;
  - назначение в диалоге с разделами «Из 1С» и «Из системы»; если в 1С преподаватели не указаны, это видно сразу;
  - статус с датой смены, клик открывает историю шаблона;
  - все действия строки собраны в меню «…» с иконками, «Открыть» стоит первым.
- «Обновлено из 1С» показывает последнюю синхронизацию. Диалог изменений оформлен таблицей «Поле / Было / Стало».
- Список шаблонов преподавателя оформлен как таблица комплекта: статус с датой, строка «Моя отметка», одно меню «…».
- Редактор: тексты РПД и комментарии сохраняются кнопкой, у комментария указано ФИО автора, статус сохранения — внизу панели разделов.
- «Содержание дисциплины»: таблица оформлена как в 1.5, у заголовка — подсказка с правилами расчёта, предупреждение о расхождении часов стало аккуратнее.
- Навигация и меню профиля как в 1.5, «Настройки» — под переключателем ролей.
- Все диалоги получили линии под заголовком и над кнопками, а секции внутри разделены линиями. Управление пользователями оформлено как таблица комплекта.
- Документация переведена в светлую тему, текст и скриншоты соответствуют новому интерфейсу.

### Удалено

- Подтверждение «Просмотрено» для изменений из 1С и маршрут `POST /api/acknowledge-field-changes`.

### Как обновиться

- С 1.x — шаги из раздела 2.1.0 «Как обновиться с 1.x», но с командой `./deploy.sh v2.1.2`.
- С 2.1.x — `cd ~/rpd-app/rpd-constructor/deploy && ./deploy.sh v2.1.2`.

## [2.1.1] — 2026-09-29

Исправление перехода с 1.x. Обновляйтесь с 1.x сразу на эту версию: на 2.1.0 базовая миграция останавливается на данных прода.

### Исправлено

- Базовая миграция переводит в коды подписи статусов, которые клиент 1.x местами записывал в историю шаблонов («Выгружен из 1С», «Создан», «Отправлен преподавателю», «Взят в работу»). Раньше она останавливалась с ошибкой «Неизвестный статус template_status».
- При откате первой выкладки `deploy.sh` сообщает, восстановлена ли БД на самом деле.

## [2.1.0] — 2026-09-29

Первая версия 2.x для прода: выкладка одной командой и конфигурация, совпадающая с сервером. С 1.x обновляйтесь сразу на 2.1.1.

### Добавлено

- Выкладка одной командой: `deploy/deploy.sh vX.Y.Z` на сервере. Образы собираются, пока работает старая версия; затем API останавливается, делается дамп БД, применяются миграции, новая версия запускается и проверяется через `/api/health`. При сбое скрипт откатывается сам: возвращает прежнюю версию, а БД восстанавливает из дампа, если миграции успели её изменить.
- `GET /api/health` — проверка БД и версия сервера.
- Миграции отдельными файлами `rpd-server/app/migrations/versions/NNNN_имя.ts` с журналом `schema_migrations`: каждая выполняется один раз и в своей транзакции. Новая создаётся командой `bun run migrate:new <имя>`.
- `dev/compose.yaml` — PostgreSQL 17 для локальной разработки.
- Репетиция выкладки `cd e2e && bun run test:deploy` на отдельном Compose-проекте.
- Список разрешённых адресов CORS через `ALLOWED_ORIGINS`.

### Изменено

- Продовая конфигурация перенесена в `deploy/`: `compose.yaml`, `deploy.sh`, `.env.example`; секреты — в `deploy/.env`. Compose совпадает с сервером: PostgreSQL 17, порты только на 127.0.0.1, HTTPS завершает nginx хоста, nginx клиента работает по HTTP. Пароль БД больше не хранится в git.
- `rpd-server/.env.example` описывает локальный запуск.
- Прежний `migrations.ts` стал миграцией `0001_baseline` и выполняется в одной транзакции: сбой больше не оставляет БД наполовину обновлённой.
- Образы собираются с bun 1.3.14 и `--frozen-lockfile`. E2E работает на PostgreSQL 17, как прод.

### Удалено

- `rpd-server/docker.sh`: вызывал `docker-compose`, которого на сервере нет.

### Как обновиться с 1.x

1. На сервере: `git clone https://github.com/xeueyysq/rpd-constructor.git ~/rpd-app/rpd-constructor`.
2. `cp ~/rpd-app/rpd-server/.env ~/rpd-app/rpd-constructor/deploy/.env` и дополнить по `deploy/.env.example` (нужны `DB_PASSWORD`, `ACCESS_TOKEN_SECRET`, `REFRESH_TOKEN_SECRET`).
3. `cd ~/rpd-app/rpd-constructor/deploy && ./deploy.sh v2.1.1` — без `--init`: скрипт найдёт том `rpd-server_postgres_data` с данными прода.

Старые клоны `~/rpd-app/rpd-server` и `~/rpd-app/rpd-client-ts` не удаляйте до успешной выкладки. Если после сбоя скрипт не сможет поднять прежнюю версию, он восстановит БД и подскажет команду `cd ~/rpd-app/rpd-server && docker compose up -d`. Подробности — в README, раздел «Развёртывание».

## [2.0.0] — 2026-09-29

Мажорная версия: сменились стек и сборка, а миграции БД несовместимы с сервером 1.x.

**На прод не выкладывать:** compose этой версии использует PostgreSQL 16 и не совпадает с сервером (там PostgreSQL 17 и nginx хоста). Обновляйтесь сразу до 2.1.1.

### Платформа

- Сервер и клиент живут в одном репозитории, менеджер пакетов — bun, Docker-образы собираются на Node 22 и bun.
- Сервер переписан на TypeScript (ESM, Node 22.18+ запускает `.ts` без сборки) и Express 5, типизация строгая. Удалены мёртвый код и неиспользуемые зависимости.
- Клиент обновлён до React 19, MUI 9 и Vite 8. CASL подключается через `AbilityProvider`, границы слоёв FSD проверяет ESLint.
- Появились тесты: Vitest на клиенте, `node --test` на сервере, E2E-сценарии Playwright против настоящих сервера и клиента на тестовой БД.

### Добавлено

- Админ создаёт и редактирует пользователей; вместо удаления пользователь деактивируется.
- Преподаватели назначаются на шаблон по аккаунтам. У РПД есть статусы, отметки готовности («сдают все») и возврат на доработку. Доступ к шаблонам и комплектам определяется владением и привязкой.
- Изменения, пришедшие из 1С, вступают в силу после подтверждения РОП.
- Совместная работа в редакторе: поле сохраняется при уходе фокуса, видно, кто сейчас в шаблоне и кто внёс последние правки. Одновременная правка одного поля не затирает чужие изменения.
- ФОС комплекта выгружается в Excel по образцу листа «вопросы».
- Колонка «Контроль» в PDF и Word.
- Инструкция по ролям (РОП, преподаватель, администратор) со скриншотами.

### Изменено

- Таблица «Содержание дисциплины» считает часы по формуле учебного плана. Часы 1С разбирает сервер, разбивку и данные 1С правят РОП и админ.
- Поиск книг нормализует запрос и ранжирует выдачу. Ошибки каталога понятны пользователю, выбор можно сбросить, в списке литературы нет дублей.
- ФОС собирается только на странице комплекта.
- Обновлены зависимости.

### Исправлено

- Фильтр и сортировка таблиц работают по видимым ФИО, роли и статусу.
- Преподаватель отображается после отправки РПД: в диалоге импорта видны участники, а при пустом ФИО выводится логин.
- Комментарии РОП привязаны к профильному шаблону и больше не пропадают при обновлении комплекта из 1С.
- Регистрация пользователя.

### Удалено

- Отложенное редактирование общих надписей титульного листа.

### Как обновиться с 1.x

См. разделы 2.1.1 и 2.1.0. Миграции 2.x добавляют и удаляют колонки, переносят привязку преподавателей на аккаунты и меняют внешние ключи: сервер 1.x с новой схемой несовместим, а сервер 2.x не работает со старой, поэтому на время миграций API останавливается.

## [1.5.0] — 2026-06-17

Выкладки с 6 мая по 17 июня 2026.

### Добавлено

- ФОС заполняется по компетенциям и выгружается в Word.
- Профили для селекторов подгружаются из 1С, при сопоставлении эталоном считаются данные 1С.
- Комплект обновляется данными из 1С. Дата обновления видна в статусе, импорт предупреждает о замене данных, а действия с комплектом требуют подтверждения.
- РОП получил возможности преподавателя.
- РПД выгружается в Word.
- В боковой панели появилась ссылка на документацию.

### Исправлено

- Пересчёт «Объёма дисциплины» по академическим часам.
- Валидация загрузки компетенций и разбор кода компетенции с пробелом.
- Уязвимости в зависимостях.

### Удалено

- Поле `certification` при импорте.

## [1.4.0] — 2026-03-11

Выкладки с 4 февраля по 11 марта 2026.

### Добавлено

- Валидация выгрузки 1С и повторный запрос при ошибке 1С.
- За шаблоном закрепляется несколько преподавателей, их можно выбрать из 1С и из системы. Шаблон создаётся и без преподавателя.
- UUID у комплектов и шаблонов.
- Кнопка перехода к содержанию РПД и редактирование часов содержания.
- Импорт шаблонов и фонд оценочных средств.

### Изменено

- Преподаватель не может редактировать данные из 1С.
- Объём дисциплины делится на 36, кнопка «Загрузить файл компетенций» убрана.
- Доработана страница «Место дисциплины».

### Исправлено

- «Содержание дисциплины» сохраняется независимо от ошибок в таблице.
- Получение комплекта из 1С, расчёт объёма дисциплины, сборка Docker и версия PostgreSQL.
