# Правила проекта

## Проверки

Запускайте команды из каталога соответствующего проекта; менеджер пакетов — bun.

| Проект | Проверка перед передачей изменений |
| --- | --- |
| `rpd-client-ts/` | `bun run lint && bun run typecheck && bun run build && bun run test` |
| `rpd-server/` | `bun run lint && bun run typecheck && bun run test` |

Клиентский `test` запускает Vitest, серверный — `node --test tests/*.test.ts`. Миграции и импорт из 1С не входят в эти проверки: им нужны внешние системы.

## E2E

`e2e/` — отдельный bun-пакет для UI-сценариев Playwright. Запуск: `cd e2e && bun run test:e2e`. Нужен Docker: команда сбрасывает отдельную тестовую БД PostgreSQL на порту 5433, выполняет миграции и синтетический seed, затем запускает Chromium против сервера на 8010 и клиента на 5180. После работы: `bun run db:down`. E2E не входит в быстрый gate; UI-сценарии проверяются этим набором.

## Клиент

- FSD, снизу вверх: `shared → entities → features → widgets → pages → app`. Импорты идут только вниз; внутри своего элемента свободны; между слайсами одного слоя запрещены.
- У каждого слайса есть корневой публичный API `index.ts` или `index.tsx`. В нижний слайс импортируйте только через него, без deep-импортов. `shared` и `app` проверяются как целые слои.
- `ui/` — отображение, `model/` — состояние и логика, `lib/` — чистые функции, `api/` — запросы. Конфигурация `rpd-client-ts/eslint.config.js` проверяет зависимости правилом `boundaries/dependencies`, типы элементов и алиасы задаёт явно; `boundaries/no-unknown-files` проверяет исходники слоёв.
- Новые обращения к API размещайте в `entities|features/*/api` и вызывайте через React Query хуки. Прямые вызовы `axiosBase` в компонентах уже встречаются; переносите их при работе с соответствующим кодом. Обновление поля профильного шаблона через `update-json-value` сводим к одному хуку `useUpdateTemplateField` в `entities/template`; пока это целевое правило.
- После второго повтора выносите общую реализацию в `shared`: настройки `material-react-table` в `DataTable`, подтверждение в `ConfirmActionDialog`, скачивание в `downloadBlob`, форматирование ФИО в `formatFullName`, тип статуса — один для всех потребителей. Не делайте несвязанный рефакторинг ради этого правила.
- Единственный источник новых размеров, цветов и типографики — тема MUI (`src/shared/config/theme.ts`); собственные параллельные токены не вводите. `react-hooks/set-state-in-effect` сейчас выключено в ESLint; включайте по мере рефакторинга компонентов.

## Сервер и данные

- Сервер типизирован строго: `any` запрещён, внешние данные принимаются как `unknown` и сужаются перед чтением.
- Поток изменений: route → тонкий controller → service (логика и транзакции) → model (SQL). Существующие репозитории используются для пользователей и refresh-сессий.
- Express 5 сам передаёт ошибки async-обработчиков в общий error middleware (`server.ts`); новые обработчики пишутся без `try/catch` и бросают классы из `utils/Errors.ts`. Имена колонок из запроса пропускайте через whitelist; значения передавайте параметрами SQL.
- Затронутые эндпоинты закрывайте `TokenService.checkAccess` и проверкой роли. Автора действия берите из JWT (`req.user`), а не из тела запроса. Это правило для доработок: сейчас защита маршрутов применяется не везде.
- Схему меняйте только в `app/migrations/migrations.ts`, идемпотентно. Проверяйте порядок создания таблиц с внешними ключами.
- `rpd_changeable_values` хранит общие пары `title/value`; `/api/update-json-value/:id` меняет колонку конкретного `rpd_profile_templates`. Не называйте оба механизма одним «changeable values» без уточнения.

## Объём изменений и тесты

- Чините то, что затрагиваете. Мёртвый код в зоне задачи удаляйте после проверки ссылок, включая динамические импорты и скрипты. Несвязанный рефакторинг и форматирование всего проекта не делайте.
- Для нетривиальной логики — сумм, разбора часов, переходов статусов, прав доступа — добавляйте минимум один содержательный тест.
- Коммиты на русском, через GitButler (`but`). Небольшие фиксы — `but land`, фичи и крупные фиксы — PR. Заголовок кратко называет изменение; в теле идут разделы `Проблема`, `Причина`, `Что сделано`, `Как проверить`.
